## 0. บริบท

อ่าน `CLAUDE.md` และ `prompt-4-design.md` ก่อน รอบ 4 เสร็จแล้ว (เงื่อนไข / กิ่ง / `firstOf` / ปุ่ม "ถ้าตัด / ถม" / แท็บ Logic)

ผู้ใช้ใช้งานบ่อยมาก: **"จุดนี้ต้องสูงกว่า / ต่ำกว่า อะไรสักอย่าง อย่างน้อย X ม. (และ/หรือ อย่างมาก Y ม.)"** เช่น
- ฐานรากหินเรียง (`base_rock-pitching.cs`) ต้องลึกจากผิวดินอย่างน้อย 2 ม.
- สันคันดิน/เขื่อนต้องสูงกว่าระดับน้ำออกแบบอย่างน้อย freeboard
- ก้นคูต้องต่ำกว่าไหล่ทางอย่างน้อย 0.5 ม. แต่ไม่เกิน 1.5 ม.

ตอนนี้ทำได้แค่ (1) "ขอบเขตค่า" = บีบค่า parameter (ไม่รู้เรื่องผิวดิน / จุดอื่น) หรือ (2) เขียนนิพจน์ `max()` / `min()` เอง — ไม่ friendly
ผู้ใช้อยากได้ **ปุ่มสำเร็จรูปแบบเดียวกับ "ถ้าตัด / ถม"** ที่ **ถามเป็นภาษาคน** ว่า "ให้จุดนี้ สูง/ต่ำ กว่า อะไร อย่างน้อย/อย่างมาก เท่าไร"

ไฟล์ที่ต้องอ่าน: `spec.js` (evaluate, ชนิดจุด, `addCutFill` เป็นแบบอย่างของ wizard), `ui.js` (หน้าต่าง ถ้าตัด / ถม, Properties ของจุด, แท็บ Logic),
`CodeGenerator.cs` (`PointLine`, helpers, ส่วน logic), `expr.js` / `SpecExpr.cs` (`ground()`, `exists()`), `ops.js` (Move/Rotate ของจุดที่มีของผูก),
`base_rock-pitching.cs` บรรทัด ~150–170 (พฤติกรรม "น้อยกว่า 2 ใช้ 2 แทน + เตือน" ที่ผู้ใช้คุ้น)

กติกาเดิมใน `CLAUDE.md` ใช้ทั้งหมด (CRLF, UI ไทย, localhost, ห้ามทำของเดิมพัง, ห้ามแก้ .cs ของผู้ใช้ระหว่างทดสอบ, ห้าม commit/push เอง,
อัปเดต README + สถานะใน CLAUDE.md, บอกเรื่อง run-viewer.bat, ห้ามเพิ่ม API ปลอมใน shim, shortcut ใหม่อยู่ในตาราง `?`)

## 1. ปุ่ม + หน้าต่างถาม (wizard)

ปุ่มใหม่ในกลุ่ม **Logic** ของ drawer ชื่อเสนอ **"สูง / ต่ำ อย่างน้อย"** (ไอคอน SVG แบบเดียวกับปุ่มอื่น: จุด + ลูกศรขึ้นลง + เส้นขีดขอบเขต)
1. คลิก **จุดที่จะคุม** (หรือเลือกจุดไว้ก่อนแล้วกดปุ่ม) — ต้องเป็นจุดที่วาดแล้ว
2. หน้าต่างถามเป็นประโยคเดียวอ่านรู้เรื่อง (ช่องเติมคำ):

   > จุด **P5** ต้อง [ **ต่ำกว่า ▾** | สูงกว่า ] [ **ผิวดิน ▾** ] อย่างน้อย [ **2** ] ม.  ☐ และไม่เกิน [ __ ] ม.

   - **อ้างอิง** (dropdown):
     - **ผิวดิน** ที่ตำแหน่งของจุดนี้ (`ground(P5)`) — เลือก target ได้ถ้ามีหลายผิว
     - **จุดอื่น** — คลิกบนรูปได้ (snap) หรือเลือกจากรายการ
     - **ระดับจริง** (เช่น ระดับน้ำออกแบบ) — ใส่ตัวเลข/parameter เป็น**ระดับจริง** (ไม่ใช่เทียบ origin) — ต้องแปลงด้วยระดับ origin ของ subassembly ทั้ง JS และ C#
   - **ระยะ** อย่างน้อย / อย่างมาก เป็นนิพจน์ได้ + ติ๊ก "สร้าง parameter" (ชื่อเสนอ เช่น `MinDepth`, `MaxDepth`, `Freeboard`) แบบหน้าต่างถ้าตัด / ถม
   - **ถ้าไม่ผ่าน ให้…** (default แรก): **ขยับจุดให้ถึงขอบ + เตือน** (แบบ rock-pitching) / ขยับเงียบๆ / เตือนอย่างเดียว ไม่ขยับ
   - **ขยับแบบไหน** (แสดงเฉพาะที่เกี่ยว): จุดแบบ ห่างจากจุด (dx, dy) = **แนวดิ่ง** · จุดแบบ ลาด + ความยาว / ระยะ + มุม = **ยืด/หดตามแนวลาดเดิม** (default) หรือแนวดิ่ง
   - แถวพรีวิวสด: "ตอนนี้ P5 ต่ำกว่าผิวดิน 1.40 ม. → จะถูกปรับเป็น 2.00 ม." + เส้นประบนรูปแสดงขอบที่ยอมได้
3. ตกลง → undo ได้ครั้งเดียว · จุดที่อ้าง P5 (ปลาย link, จุดต่อ, shape) ขยับตามเองเพราะเป็นตำแหน่งของ P5 หลังปรับ

จุดที่ใช้ไม่ได้ (ขึ้นเหตุผลในหน้าต่าง ไม่ใช่ error): origin, จุดจากโค้ดเดิม (external), `firstOf`, ลาดจนชนดิน (ตำแหน่งถูกกำหนดโดยผิวดินอยู่แล้ว — เสนอทางอื่นในข้อความ)
จุดหนึ่งมีขอบเขตได้ **ชุดเดียว** (ทั้งอย่างน้อยและอย่างมากในชุดเดียว) — กดซ้ำ = แก้ชุดเดิม

## 2. การเก็บใน spec + การคำนวณ

เสนอ (ปรับได้ อธิบายใน M0 พร้อมตัวอย่าง JSON + C#):
```jsonc
{ "id": "P5", "def": { ... เดิม ... },
  "limitY": { "side": "below",                      // below = ต้องต่ำกว่าอ้างอิง, above = ต้องสูงกว่า
              "ref": { "type": "ground", "target": "TargetSurface" },   // | { "type": "point", "id": "P1" } | { "type": "elev", "expr": "DesignWL" }
              "min": "MinDepth", "max": null,      // นิพจน์ (ระยะ ≥ 0) อย่างใดอย่างหนึ่งหรือทั้งคู่
              "action": "clampWarn",               // clampWarn | clamp | warn
              "along": "slope" } }                  // vertical | slope
```
- ลำดับ: คำนวณ def เดิม → ใช้ `limitY` → (ถ้าอยู่ในกลุ่มหมุน ต้องตกลงลำดับให้ชัด — เสนอ: ไม่อนุญาต limit กับสมาชิกกลุ่มหมุน รอบนี้ เตือนตอนสร้าง)
- อ้างอิงคำนวณไม่ได้ (ไม่มีผิวดินตอน Layout, จุดอ้างอิงไม่เกิด) → ไม่ปรับ + เตือนสีเหลือง (ตัดสินแบบเดียวกันทั้ง JS / C#) — ไม่ทำให้จุดหายไป
- min > max → error ภาษาไทยตอนตั้ง และตอนรันใช้ min + เตือน
- ฝั่ง Left (F = -1): ขอบเขตเป็นแนวดิ่ง จึงไม่กลับ แต่ "ยืดตามแนวลาด" ต้องใช้ทิศลาดที่ mirror แล้ว — มี test
- ชนิดจุดที่อ้าง P5 ด้วย `P5.y` ในนิพจน์ เห็นค่าหลังปรับ
- **ใช้กับ logic ได้**: เพิ่มในนิพจน์ `limited(P5)` = จริงเมื่อรอบนี้ถูกปรับ (เช่น ถ้าถูกบังคับลึก ให้มีชั้นหินรองเพิ่ม — ใช้เป็น test ของ decision ได้)
- ใน Layout mode / scenario: แสดงผลตามผิวดินของ scenario เหมือนส่วนอื่น

## 3. โค้ด C# ที่สร้าง

- helper ใหม่ เช่น `LimitY(cs, "P5", pt, refY, below, min, max, action, slopeDirOrNull)` คืน `Pt?` + เตือนด้วย `CorridorError` ที่มีจริง
  (ดู enum ที่ verify แล้วใน shim — ห้ามประดิษฐ์ค่าใหม่) ข้อความเตือนแบบเดียวกับ rock-pitching: `"P5 ลึกจากผิวดิน 1.40 m < 2.00 m ใช้ 2.00 m แทน"`
- อ้างอิงผิวดินใช้ helper `Ground(...)` ที่รอบ 4 มีแล้ว · ระดับจริงแปลงด้วยระดับ origin ของ subassembly (`CurrentSubassemblyElevation` ตามที่ shim ทำ)
- บรรทัดอยู่ติดกับบรรทัดคำนวณ P5 และ codelink ชี้ได้ (คลิกป้ายขอบเขต → บรรทัด `LimitY`)
- โค้ดอ่านง่าย มีคอมเมนต์ไทย เช่น `// P5 ต้องต่ำกว่าผิวดินอย่างน้อย MinDepth (ถ้าไม่ถึง: ขยับลงตามแนวลาดเดิม + เตือน)`

## 4. หน้าจอหลังสร้าง

- บนรูป: จุดที่มีขอบเขตมีไอคอนเล็ก (ลูกศรขึ้นลง) · เลือกจุดแล้วเห็น **แถบช่วงที่ยอมได้** (เส้นประ min / max เทียบอ้างอิง) · ตอนถูกปรับ จุดเดิมก่อนปรับแสดงจางๆ + ลูกศรไปตำแหน่งใหม่
- **Properties ของจุด**: หัวข้อ "ขอบเขตความสูง" แสดงประโยคเดียวกับในหน้าต่าง (แก้ได้ในที่) + ปุ่มลบ + ค่าตอนนี้ ("ลึก 2.00 ม. — ถูกปรับ +0.60")
- **แท็บ Logic**: ส่วนใหม่ "ขอบเขตความสูง" รายการทุกจุดที่มีขอบเขต + สถานะสด (ผ่าน / ถูกปรับ / ไม่รู้ค่า) + ปุ่มโค้ด
- **Scenario**: scenario ไหนทำให้ขอบเขตทำงาน (ถูกปรับ) แสดงในรายการ — ช่วยให้ทดสอบครบทั้งกรณี "ผ่าน" และ "ถูกปรับ"
- Messages: เตือนสีเหลืองแบบเดียวกับใน C#
- README: หัวข้อใหม่ + ตารางสั้น "ใช้อันไหนเมื่อไร": ขอบเขตค่า (บีบค่า parameter) / สูง-ต่ำ อย่างน้อย (บีบตำแหน่งจุดเทียบผิวดิน/จุด/ระดับ) / ถ้าตัด-ถม (เลือกรูป)

## 5. ต่อกับระบบเดิม

Move / Copy / Paste / Rotate (ดูข้อ 2), Delete (ลบจุดอ้างอิง → ขอบเขตที่อ้างมันถูกถามว่าจะลบด้วยไหม), undo/redo, auxiliary (จุด aux มีขอบเขตได้),
กิ่ง (จุดในกิ่งมีขอบเขตได้; อ้างจุดในกิ่งอื่น = เตือนแบบ `branchRisks`), spec ฝังใน .cs (`sa-spec`), ไฟล์ import (ส่วนที่วาด)

## 6. Test

- JS: ทุกชนิดอ้างอิง (ผิวดิน / จุด / ระดับจริง) × สูงกว่า/ต่ำกว่า × min / max / ทั้งคู่ × แนวดิ่ง / แนวลาด × Right / Left; ไม่มีผิวดิน; จุดอ้างอิงไม่เกิด;
  min > max; จุดที่อ้าง P5 ขยับตาม; `limited()`; undo/redo; Copy คงขอบเขต (อ้างจุดในชุดที่ copy = อ้างตัวใหม่)
- C#: เทียบผล JS กับโค้ดที่สร้างในหลายผิวดิน (ผ่าน / ถูกปรับ / ไม่รู้ค่า) ทั้ง Right / Left และเทียบข้อความเตือน
- กรณีเทียบ rock-pitching: วาดฐานลึก `Depth` ด้วยขอบเขต "ต่ำกว่า ... อย่างน้อย 2" แล้วผลตรงกับ `base_rock-pitching.cs` เมื่อ Depth = 1.5 และ 3
  (copy ไฟล์ไปทดสอบที่อื่น ห้ามแก้ไฟล์จริง)
