## 1. เก็บใน spec (ข้อ 2 ของ prompt)

```jsonc
{ "id": "P5", "codes": ["Base"], "def": { "type": "slopeLength", "from": "P4", "slope": "-1/0.5", "length": "Depth", "dir": 1, "measure": "dy" },
  "limitY": {
    "side": "below",                                   // below = ต้องต่ำกว่าอ้างอิง · above = ต้องสูงกว่า
    "ref": { "type": "ground", "target": "TargetSurface" },   // ผิวดินที่ offset ของจุดนี้
        // | { "type": "point", "id": "P1" }           // ระดับของจุดอื่น
        // | { "type": "elev", "expr": "DesignWL" }    // ระดับจริง (ไม่ใช่เทียบ origin) — นิพจน์ / parameter
    "min": "MinDepth",                                 // ระยะดิ่งอย่างน้อย (นิพจน์ ≥ 0) · null = ไม่คุม
    "max": null,                                       // ระยะดิ่งอย่างมาก · null = ไม่คุม (ต้องมีอย่างน้อยหนึ่งอย่าง)
    "action": "clampWarn",                             // clampWarn = ขยับ + เตือน · clamp = ขยับเงียบ · warn = เตือนอย่างเดียว
    "along": "slope" } }                               // vertical = แนวดิ่ง · slope = ตามแนวเดิมของจุด
```

- **ระยะ** = ระยะ **ดิ่ง** จากอ้างอิง: `below` → `d = ref − y` · `above` → `d = y − ref` · ไม่ผ่าน = `d < min` หรือ `d > max` → ขยับให้ `d` = ขอบที่ใกล้ที่สุด
- ชื่อ field `limitY` ตามที่ prompt เสนอ — วันหลังเพิ่ม `limitX` (ขอบเขตแนวราบ) ได้โดยไม่ชนกัน
- จุดหนึ่งมี `limitY` ได้ชุดเดียว · ฟังก์ชันล้วนใน `spec.js`: `setLimit(spec, pointId, limit)` / `removeLimit(spec, pointId)` / `limitCheck(spec, pointId, limit)` (คืนเหตุผลที่ใช้ไม่ได้) — prompt-5 ข้อ 1 เอาไปรวมใน Logic API ได้เลย

### "ตามแนวเดิม" (along = slope) แปลว่าอะไรในแต่ละชนิดจุด

| ชนิดจุด | ขยับแบบไหนได้ | ตามแนวเดิม = |
|---|---|---|
| ห่างจากจุด (dx, dy), บนผิวดิน, จุดตัดของ 2 เส้น | แนวดิ่งเท่านั้น | — |
| ลาด + ความยาว | **ตามแนวลาด** (default) / แนวดิ่ง | ยืด / หดตามเส้นจาก `from` ด้วย slope เดิม (ความชันไม่เปลี่ยน) |
| ระยะ + มุม | **ตามแนวมุม** (default) / แนวดิ่ง | ยืด / หดตามเส้นจาก `from` ที่มุมเดิม |
| บนเส้นระหว่าง 2 จุด | ตามเส้น a–b / แนวดิ่ง | เลื่อน t บนเส้น a–b (ต่อเส้นออกไปได้) |
| origin, จุดจากโค้ดเดิม, จุดแรกที่เกิด, ลาดจนชนดิน, จุดสัมผัส (Fillet), สมาชิกกลุ่มหมุน | **ตั้งไม่ได้** — หน้าต่างบอกเหตุผล | ลาดจนชนดิน: เสนอให้คุมจุดที่มันเริ่ม / ใช้ "ถ้าตัด / ถม" แทน |

- เส้นแนวเดิมเกือบราบ (ความชัน ≈ 0) ขยับขึ้นลงตามแนวนั้นไม่ได้ → ใช้แนวดิ่งแทน + เตือน
- **อ้างอิงผิวดิน + ตามแนวลาด**: พอจุดขยับตามลาด offset เปลี่ยน ระดับดินก็เปลี่ยน → หาตำแหน่งบนเส้นลาดเดิมที่ "ระยะจากดิน ณ ตำแหน่งใหม่ = ขอบ" ให้ตรงจริง
  (วิธีเดียวกันทั้ง JS / C#: ไล่หาช่วงแล้วแบ่งครึ่ง ไม่เกิน 50 m) — ไม่เจอคำตอบ = ใช้แนวดิ่ง + เตือน

### ลำดับการคำนวณ / กรณีพิเศษ

1. คำนวณ `def` เดิม → 2. ใช้ `limitY` → 3. จุด / link / shape / นิพจน์ที่อ้าง P5 (`from`, `P5.y`, `ground(P5)`) เห็นตำแหน่ง**หลังปรับ**
- อ้างอิงคำนวณไม่ได้ → **ไม่ปรับ + เตือนสีเหลือง** จุดไม่หาย:
  - ผิวดิน: ไม่ได้กำหนด target = เตือน · **Layout mode = ไม่ปรับและไม่เตือน** (เหมือน `ground()` / ลาดจนชนดินใน Layout ตอนนี้ — assembly ไม่ขึ้นเตือนเยอะ)
  - จุดอ้างอิงหาไม่ได้ / ไม่เกิดเพราะกิ่ง = ไม่ปรับ + เตือน · อ้างจุดของกิ่งอื่น = ⚠ ตอนออกแบบแบบ `branchRisks`
- `min > max` → หน้าต่าง / Properties ไม่ยอม (ข้อความไทย) · ตอนรัน (เช่น parameter ทำให้ min > max) ใช้ `min` + เตือน
- ฝั่ง Left (F = -1): ขอบเขตเป็นแนวดิ่ง ไม่กลับ · แนวลาดใช้ทิศที่ mirror แล้ว (ตำแหน่งจริงของเส้น) — มี test
- จุดในกิ่ง / จุด auxiliary มีขอบเขตได้ · จุดที่ไม่เกิด = ไม่คำนวณขอบเขต
- นิพจน์ใหม่ **`limited(P5)`** = จริงเมื่อรอบนี้ P5 ถูกขยับ · ไม่ถูกขยับ / ไม่รู้ค่า / P5 ไม่เกิด = เท็จ (ไม่ error แบบ `exists()`) · P5 ไม่มีขอบเขต = ช่องขึ้นแดงตอนพิมพ์
- **ระดับจริง** (`elev`): ค่าในช่องเป็นระดับจริง → เทียบ origin = ค่า − ระดับ origin
  (JS: ระดับ origin ของ subassembly บนจอ = `elevOf(origin.y)` · C#: `cs.CurrentElevation` ที่โค้ดรอบ 4 ใช้อยู่แล้ว · test ใช้ 100 ทั้งคู่)

## 2. โค้ด C# ที่จะได้ (ข้อ 3 ของ prompt)

ตัวอย่าง: ฐานราก P5 ต้องต่ำกว่าผิวดินอย่างน้อย `MinDepth` (ขยับตามแนวลาด + เตือน) และ สัน P2 ต้องสูงกว่าระดับน้ำ `DesignWL` อย่างน้อย `Freeboard`:

```csharp
        Pt? P2 = Delta(cs, "P2", P1, F * Width, 0.0);   // P2 ห่างจาก P1
        // P2 ต้องสูงกว่าระดับ DesignWL อย่างน้อย Freeboard (ถ้าไม่ถึง: ขยับขึ้นแนวดิ่ง + เตือน)
        P2 = LimitY(cs, "P2", P2, null, Lim.Above, () => DesignWL - cs.CurrentElevation, "ระดับ DesignWL", Freeboard, null, Lim.ClampWarn);

        Pt? P5 = SlopeLength(cs, "P5", P4, -2.0, Depth, F * 1.0, Measure.Dy);   // P5 ลาด + ความยาว
        // P5 ต้องต่ำกว่าผิวดินอย่างน้อย MinDepth (ถ้าไม่ถึง: ขยับลงตามแนวลาดเดิม + เตือน)
        P5 = LimitY(cs, "P5", P5, P4, Lim.Below, x => GroundAt(cs, surface, x), "ผิวดิน", MinDepth, null, Lim.ClampWarn);
        bool P5_limited = Limited(cs, "P5");                              // มีเฉพาะเมื่อมีนิพจน์ใช้ limited(P5)
```

- `LimitY` คืน `Pt?` (null เข้า = null ออก) · อ้างอิงเป็นฟังก์ชันของ offset (ผิวดิน) หรือค่าคงที่ (จุด / ระดับ) · `along` ส่งจุดต้นของแนวเดิม (P4) หรือ null = แนวดิ่ง
- เตือนด้วย `Warn(cs, CorridorError.ValueTooSmall / ValueTooLarge, ...)` (มีจริงใน API — ใช้ใน `base_rock-pitching.cs` แล้ว) · อ้างอิงหาไม่ได้ = `LogicalNameNotFound` / `Failure` แบบเดิม
- ข้อความแบบ rock-pitching: **`P5 ลึกจากผิวดิน 1.40 m < 2.00 m ใช้ 2.00 m แทน`** · `P2 สูงกว่าระดับ DesignWL 0.30 m < 0.50 m ใช้ 0.50 m แทน` · `P7 ลึกจาก P2 1.80 m > 1.50 m ใช้ 1.50 m แทน`
- บรรทัด `LimitY` อยู่ติดบรรทัดคำนวณจุด · codelink: P5 ชี้ทั้งสองบรรทัด, ป้ายขอบเขตบนรูป → บรรทัด `LimitY`
- ไม่เพิ่ม API ใน shim (ใช้ `CurrentElevation`, `CurrentOffset`, `Elevation` / `SampleSection` ที่โค้ดรอบ 4 ใช้อยู่แล้ว)

## 4. คำถาม (ข้อ 9 ของ prompt + ที่เพิ่มจาก M0) — **คำตอบที่เสนอ อยู่ในวงเล็บตัวหนา**

### โครงข้อมูลที่ปรับตามคำตอบ (แทน `limitY` ในข้อ 1)

```jsonc
"limit": {
  "measure": "depth",          // สิ่งที่คุม (เลือกในหน้าต่าง):
                               //   depth  = ระยะดิ่ง ต่ำกว่า / สูงกว่า อ้างอิง (ผิวดิน / จุด / ระดับจริง)
                               //   normal = ระยะตั้งฉากกับผิวดิน ต่ำกว่า / สูงกว่า ผิวดิน (ตั้งฉากกับช่วงผิวดินที่อยู่ใต้ / เหนือจุด)
                               //   length = ความยาวจากจุดต้นของจุดนี้ (from / a) ตามแนวเดิม — ไม่ต้องมีอ้างอิง
                               //   offset = ระยะราบจากอ้างอิง (จุด / แกน origin) ออกด้านนอก (+) — แทน limitX ที่ prompt บอกไว้ทีหลัง
  "side": "below",             // depth / normal: below | above · length / offset: ไม่ใช้
  "ref": { "type": "ground", "target": "TargetSurface" },   // depth: ground | point | elev · normal: ground · offset: point | origin · length: ไม่มี
  "min": "MinDepth", "max": null,
  "action": "clampWarn",       // clampWarn | clamp | warn
  "along": "slope"             // ขยับแบบไหน: vertical | slope (ตามแนวเดิม) | horizontal — ตัวเลือกที่เหลือตามชนิดจุดและสิ่งที่คุม
}
```

- ทุกแบบใช้วิธีเดียวกัน: **ขยับจุดตามทาง (`along`) จนค่าที่คุมเท่าขอบ** (ไล่หาช่วงแล้วแบ่งครึ่ง เหมือนกันทั้ง JS / C# ภายใน 50 m) — แนวดิ่งกับระยะดิ่งคำนวณตรงได้เลย
- ขยับไปทางไหนก็ค่าที่คุมไม่เปลี่ยน (เช่น คุมความยาวแต่ขยับแนวดิ่ง) → หน้าต่างไม่ให้เลือกคู่นั้น
- `length` ใช้ได้กับจุดที่มีจุดต้น: ห่างจากจุด (dx, dy), ลาด + ความยาว, ระยะ + มุม, บนเส้นระหว่าง 2 จุด · ขยับตามแนวเดิมเท่านั้น
- `offset` (ระยะราบ) ขยับได้ตามแนวเดิม / แนวราบ — ฝั่ง Left วัดออกด้านนอกเหมือนกัน (ค่าในกรอบ Right)
- เตือน: `P5 ลึกจากผิวดิน 1.40 m < 2.00 m ใช้ 2.00 m แทน` · `P5 ห่างตั้งฉากจากผิวดิน …` · `P5 ยาวจาก P4 3.20 m > 3.00 m ใช้ 3.00 m แทน` · `P5 ห่างแนวราบจาก P1 …`
- ฟังก์ชันล้วน: `setLimit(spec, pointId, limit)` / `removeLimit` / `limitOptions(spec, pointId)` (คืนว่าคุมอะไรได้ / ขยับแบบไหนได้ / เหตุผลที่ไม่ได้) — ใช้ทั้งหน้าต่างและ Logic API ของ prompt-5
- ทำจริงใน M1: "ตามแนวเดิม" ใช้ได้กับทุกจุดที่มีจุดต้น (ห่างจากจุด dx/dy, ลาด, มุม, บนเส้นระหว่าง 2 จุด — แทนตารางในข้อ 1 ที่ให้ dx/dy แนวดิ่งอย่างเดียว) ·
  ข้อความเตือนใช้คำเดียวกับในประโยค: `P5 ต่ำกว่าผิวดิน 1.40 m < 2.00 m ใช้ 2.00 m แทน` / `P5 สูงกว่า P2 …` / `P5 ยาวจาก P4 …` / `P5 ห่างแนวราบจากแกน …`
- C#: `LimitY` ในข้อ 2 เปลี่ยนเป็น `Limit(cs, "P5", P5, start, measure, refFn, side, min, max, action, along)` — รูปแบบบรรทัด / คอมเมนต์ / codelink เหมือนที่เสนอ
