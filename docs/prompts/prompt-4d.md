# งานรอบ 4d (สั้น): ลากปรับความกว้างแถบซ้าย / ขวา — ทำก่อน prompt-5

> วิธีใช้: สั่ง Claude Code ว่า "อ่าน CLAUDE.md กับ prompt-4d.md แล้วทำเลย" — งานเล็ก ทำรวดเดียวไม่ต้องแบ่ง milestone แล้วหยุดให้ผู้ใช้ลอง

## ปัญหา
ผู้ใช้ลองวาด rock-pitching แล้วพบว่าแถบซ้าย (ต้นไม้ Workspace) **แคบเกินไปและยืด / หดไม่ได้** — prompt-5 จะเพิ่ม Conditions / Variables ในต้นไม้ซ้าย ยิ่งต้องกว้างขึ้น
ตอนนี้ความกว้างตายตัวใน `SA.Web/wwwroot/css/app.css`:
- บรรทัด ~40: `grid-template-columns: 280px minmax(0,1fr) 300px` (ซ้าย / workspace / ขวา)
- บรรทัด ~41: `body.editing { grid-template-columns: 280px minmax(280px,var(--edw,40vw)) minmax(0,1fr) 300px }` (มีแถบโค้ดแทรก — มีตัวแปร `--edw` อยู่แล้ว ดูว่ามีตัวลากของ editor อยู่หรือไม่ แล้วใช้กลไกเดียวกัน)
- บรรทัด ~419: จอแคบเรียงเป็นแถวเดียว (ห้ามพัง)

## ที่ต้องทำ
1. **ตัวลากขอบ** (แบบ VS Code): ขอบขวาของแถบซ้าย และขอบซ้ายของแถบขวา — เมาส์ชี้แล้วเคอร์เซอร์เป็น `col-resize` + เส้นไฮไลต์บางๆ, ลากแล้วกว้างตามทันที
2. ใช้ตัวแปร CSS เช่น `--lw` / `--rw` แทนเลข 280px / 300px ในทั้งสองบรรทัด (ปกติ และ `body.editing`)
3. **ขอบเขต**: ซ้าย 200–600 px, ขวา 240–600 px และ workspace ตรงกลางต้องเหลืออย่างน้อย ~320 px (ถ้าจอเล็ก ให้บีบแถบก่อน)
4. **ดับเบิลคลิกที่ขอบ** = คืนค่าเริ่มต้น (280 / 300)
5. **จำความกว้างไว้ในเบราว์เซอร์** (ที่เดียวกับค่าอื่นที่เว็บจำไว้อยู่แล้ว เช่น ต้นไม้ที่กางไว้) — อ่าน / เขียนแบบ try/catch ถ้าอ่านไม่ได้ใช้ค่าเริ่มต้น
6. ระหว่างลากและหลังลาก: workspace วาดใหม่ให้พอดี (resize ของ SVG / view เหมือนตอนย่อขยายหน้าต่าง) รูปไม่เพี้ยน, ไม่ไปเลือก / ลาก object ใน workspace โดยไม่ตั้งใจ
7. ต้นไม้ซ้าย: ชื่อยาวให้ตัด `…` พร้อม tooltip ชื่อเต็ม แทนการล้นหรือขึ้นบรรทัดใหม่ (ตรวจว่าตอนนี้เป็นยังไง)
8. จอแคบ (กฎบรรทัด ~419) ยังทำงานเหมือนเดิม — ซ่อนตัวลากในโหมดนั้น
