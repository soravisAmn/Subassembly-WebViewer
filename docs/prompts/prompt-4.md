## 1. จัดระเบียบ repo (ทำใน Milestone 0 — ทุกขั้นที่แตะ git ต้องขออนุญาตผู้ใช้ก่อน)

ปัญหาที่เจอตอนผู้ใช้สลับเครื่อง:
- โฟลเดอร์ `bin/` และ `obj/` ของทุกโปรเจกต์ถูก commit ไว้ → build ทีไรไฟล์เปลี่ยนเต็ม `git status` และจะ conflict ระหว่างสองเครื่อง
- ใน commit ไฟล์เป็น LF แต่ไฟล์ในเครื่องเป็น CRLF (กติกาโปรเจกต์) → `git diff` บอกว่าเปลี่ยนทั้งไฟล์ ทั้งที่เนื้อหาเหมือนเดิม
  (ตรวจแล้ว: `git diff --ignore-cr-at-eol` เหลือแค่ `pavement-assembly.cs` — ไฟล์ของผู้ใช้ ห้ามแตะ)

ให้เสนอแล้วทำเมื่อผู้ใช้ตกลง:
1. `.gitignore` สำหรับ .NET (`bin/`, `obj/`, `.vs/`, ฯลฯ) + `git rm -r --cached` ของ bin/obj (ไม่ลบไฟล์ในเครื่อง)
2. `.gitattributes` ให้ไฟล์ข้อความ checkout เป็น CRLF ทุกเครื่องเสมอ (เช่น `* text=auto eol=crlf` + ระบุไฟล์ binary) แล้ว `git add --renormalize .`
3. commit แยกเป็น "จัดระเบียบ repo" (ไม่ปนกับงาน logic) — ผู้ใช้ต้องอนุญาตก่อน และบอกผู้ใช้ว่าอีกเครื่องต้องทำอะไรหลัง pull
   (เช่น ถ้ามีไฟล์ค้างแก้ในอีกเครื่อง ให้ commit/stash ก่อน pull)
4. `.claude/launch.json` เป็นของเครื่อง — ถามผู้ใช้ว่าจะ commit หรือ ignore

## 2. นิพจน์ที่เป็นเงื่อนไข

ขยาย `expr.js` + `SpecExpr.cs` (และตัวแปลงเป็น C#) ให้มี:
- เปรียบเทียบ `> < >= <= == !=` (เทียบทศนิยมด้วย tolerance เล็กๆ สำหรับ `==` / `!=` — กำหนดค่าเดียวกันทั้ง JS / C#)
- ตรรกะ `and or not` (รับ `&& || !` ด้วย) และ `if(cond, a, b)` สำหรับเลือกค่า
- **ค่าจากเรขาคณิต** (ต้องทำได้ทั้งใน JS และ C# ที่สร้าง):
  - `P3.x`, `P3.y` — offset / elevation ของจุด (เทียบ origin ในกรอบเดียวกับที่ spec ใช้; ระบุให้ชัดว่าฝั่ง Left เป็นค่าบนจอหรือค่าในกรอบ Right)
  - `ground(P3)` — ระดับผิวดิน (target surface) ที่ offset ของจุด P3, `ground(P3, "ชื่อ target")` ถ้ามีหลาย target
  - `exists(P3)` — จุดนี้เกิดหรือไม่ (เงื่อนไขของมันจริงและคำนวณได้)
  - `Side` และ parameter ทุกตัว (มีอยู่แล้ว)
- ชนิดผลลัพธ์: ตรวจตอน parse ว่าช่องที่ต้องการ "ตัวเลข" ไม่ได้ใส่ "จริง/เท็จ" และกลับกัน — ข้อความ error ภาษาไทยชี้ตำแหน่ง
- ค่าที่อ้างจุดทำให้เกิด **การพึ่งพา** → `TopoOrder` / evaluator ต้องรู้ (จุดที่เงื่อนไขอ้าง P3 ต้องคำนวณหลัง P3; วนกัน = cyclic error เหมือนเดิม)

## 3. โครงข้อมูล logic (ใช้ร่วมกับ flowchart รอบหน้า)

เสนอแบบนี้ (ปรับได้ แต่ต้องอธิบายผู้ใช้ใน M0 พร้อมตัวอย่าง JSON และ C# ที่จะได้):

```jsonc
"logic": {
  "conditions": [                       // เงื่อนไขที่ตั้งชื่อไว้ ใช้ซ้ำได้ (ใน SAC คือ Decision)
    { "id": "C1", "name": "IsCut", "expr": "ground(P2) > P2.y" }
  ],
  "branches": [                         // กิ่งของ flowchart: object ที่อยู่ในกิ่งเกิดเมื่อเงื่อนไขของกิ่ง (และกิ่งแม่ทุกชั้น) จริง
    { "id": "B1", "parent": null, "label": "ตัด", "when": "IsCut" },
    { "id": "B2", "parent": null, "label": "ถม",  "when": "not IsCut" },
    { "id": "B3", "parent": "B2", "label": "ถมสูง", "when": "P2.y - ground(P2) > 3" }
  ]
}
// แต่ละ point / link / shape / กลุ่มหมุน มี "branch": "B1" (ไม่มี = เกิดเสมอ)
```
- **ก (รอบนี้)** = แก้ `branch` ของ object + จัดการ conditions/branches ผ่านแผง Logic (ข้อ 5)
- **ข (prompt-5)** = วาด conditions/branches เดียวกันนี้เป็นแผนผัง (Decision = เงื่อนไข + กิ่ง "ใช่ / ไม่ใช่", Switch = หลายกิ่งของค่าเดียว)
  → รอบนี้ต้องเก็บข้อมูลพอให้วาดแผนผังได้: ลำดับกิ่ง, กิ่ง "ไม่ใช่" ที่คู่กับ "ใช่", กิ่ง else ของ Switch (ใส่ field ไว้ก่อนได้ ยังไม่ต้องมี UI)
- `cond` ที่จองไว้เดิม: ถ้าไม่มีใครใช้ให้ลบคอมเมนต์ทิ้งและใช้โครงใหม่แทน; ถ้ามีไฟล์ใช้อยู่ ให้อ่านแบบเข้ากันได้
- ชนิดจุดใหม่ **`firstOf`** — `{ type: "firstOf", points: ["P5", "P6"] }` = จุดแรกในรายการที่เกิด (ไว้ต่อเรขาคณิตหลังกิ่ง เช่น "จุด daylight ไม่ว่าตัดหรือถม")
  จุดที่อ้าง `firstOf` ไม่ต้องอยู่ในกิ่งก็ได้ ถ้าไม่มีสักจุดเกิด = จุดนี้ไม่เกิด + เตือน

**การคำนวณ (JS) และโค้ดที่สร้าง (C#) ต้องตรงกัน:**
- object ในกิ่งที่ไม่จริง = **ไม่เกิดแบบปกติ** (ไม่ใช่ error, ไม่ขึ้นเตือนสีแดง) — แยกให้ชัดจาก "หาจุดไม่ได้" ที่เป็น error
- object ที่อ้างจุดที่ไม่เกิดเพราะเงื่อนไข: ถ้าอยู่ในกิ่งเดียวกัน/กิ่งลูก = ไม่เกิดตามปกติ;
  ถ้าเป็น object ที่ "เกิดเสมอ" แต่อ้างจุดในกิ่ง → **ตรวจตอนวาด/ตอน Save ว่า "อาจหาจุดไม่ได้ในบางกรณี"** และเสนอทางแก้ (ย้ายเข้ากิ่ง / ใช้ `firstOf`)
- C#: คำนวณเงื่อนไขเป็น `bool` ตามลำดับการพึ่งพา, จุดในกิ่ง = `Pt? P5 = B1 ? ... : null;`, `AddPoint` / `AddLink` / `AddShape` เฉพาะที่ไม่ null
  (ไม่ `Warn` เมื่อ null เพราะเงื่อนไข) — โค้ดที่ได้ต้องอ่านง่าย มีคอมเมนต์ชื่อเงื่อนไข/กิ่งเป็นภาษาไทย และ codelink (คลิก object → บรรทัด) ใช้ได้
- เงื่อนไขที่ใช้ `ground(...)` ตอน **Layout mode** (ไม่มี target) — ตัดสินแบบเดียวกับที่ลาดจนชนดินทำตอนนี้ (บอกผู้ใช้ว่าเลือกกิ่งไหน และทำให้ตรงกันทั้ง JS / C#)
- ฝั่ง Left (F = -1), กลุ่มหมุน, auxiliary, arc/fillet, polygon — ทำงานร่วมกับกิ่งได้ทั้งหมด

## 4. ปุ่มสำเร็จรูป "ถ้าตัด / ถม"

เปิดปุ่มใน drawer (เอา `disabled` / `data-later` ออก) ทำงานแบบ wizard สั้นๆ:
1. เลือกจุดบานพับ (hinge) เช่น ขอบคันดิน/ไหล่ทาง และ target surface
2. ใส่ลาดตัด / ลาดถม (default `1:1.5` / `1:2` จากปุ่ม slope สำเร็จรูป, เป็น parameter ได้ เช่นสร้าง `CutSlope`, `FillSlope` ให้อัตโนมัติ — ถามในหน้าต่าง)
3. ได้ของชุดนี้: เงื่อนไข `IsCut = ground(hinge) > hinge.y`, กิ่ง "ตัด" / "ถม", จุดลาดจนชนดินสองจุด (หนึ่งจุดต่อกิ่ง), link ลาดสองเส้น (code ตั้งได้ default `Daylight_Cut` / `Daylight_Fill`),
   และจุด `firstOf` ชื่อ "Daylight" สำหรับต่อเรขาคณิตต่อ
- ลากจุด surface ขึ้นลงแล้วต้องเห็นรูปสลับระหว่างตัด/ถมทันที — นี่คือ demo หลักของรอบนี้
- นิยาม "ตัด" ให้ถูกตามงานจริง (ผิวดินอยู่สูงกว่าจุดบานพับ = ตัด) และอธิบายใน README; ถ้าผู้ใช้ต้องการนิยามอื่นให้ปรับได้ในเงื่อนไข

## 5. หน้าจอ (แบบ ก)

- **Properties ของ object**: ช่อง "เกิดเมื่อ (กิ่ง)" — เลือก: เกิดเสมอ / กิ่งที่มี / "+ เงื่อนไขใหม่…" (สร้างเงื่อนไข + กิ่งใช่/ไม่ใช่ให้ในครั้งเดียว)
  ใช้กับหลายชิ้นที่เลือกพร้อมกันได้ (undo ได้ในครั้งเดียว)
- **ระหว่างวาด**: มีตัวเลือก "วาดลงกิ่ง…" (banner บอกกิ่งปัจจุบัน) ให้ object ใหม่เข้ากิ่งนั้นเลย — เลือก shortcut ที่ไม่ชน (เสนอผู้ใช้)
- **แผง Logic** (ใน drawer หรือแท็บข้าง Properties): รายการเงื่อนไขพร้อม **ค่าปัจจุบัน จริง/เท็จ อัปเดตสดๆ** ตอนลาก surface / แก้ parameter,
  รายการกิ่ง (ต้นไม้ตามกิ่งแม่) + จำนวน object ในกิ่ง, คลิกกิ่ง = เลือก object ในกิ่งนั้น, แก้ชื่อ/นิพจน์/ลบ (ลบแล้วถามว่าจะเอา object ไปไว้ไหน)
- **การแสดงผล**: object ในกิ่งที่ไม่จริงตอนนี้ — ปุ่มสลับ "แสดงเฉพาะที่เกิด" (แบบ Civil 3D) / "แสดงทุกกรณี" (กิ่งที่ไม่เกิดเป็นเส้นจางประ + ป้ายชื่อกิ่ง)
  และ snap ไปของที่ไม่เกิดได้หรือไม่ ให้เสนอผู้ใช้
- **ต้นไม้ซ้าย**: object มีป้ายชื่อกิ่ง (สีเดียวกับในรูป)
- **Scenario**: ตาราง scenario เดิม เพิ่มคอลัมน์ว่าแต่ละ scenario เข้ากิ่งไหนบ้าง และสรุป **"กิ่งที่ยังไม่มี scenario ไหนทดสอบเลย"**
  (ตรงกับเป้าหมาย "ทดสอบทุก case" ของผู้ใช้)

## 6. ไฟล์ .cs ที่เขียนเอง (import)

- ส่วนที่วาดเพิ่ม (ในช่วง `SA-DRAWING BEGIN/END`) ใช้ logic ได้เหมือนกัน
- logic ในโค้ดที่ผู้ใช้เขียนเอง (if/else นอกช่วง marker) **ยังไม่ต้องแปลงเป็นกิ่ง** ในรอบนี้ — แต่ถ้าทำได้ง่าย ให้แสดงในแผง Logic ว่า
  "รอบรันนี้โค้ดเดิมเข้า if บรรทัดไหน" ได้ ให้เสนอผู้ใช้เป็นงานแยก ไม่ต้องทำเลย

## 10. คำถามที่ต้องถามผู้ใช้ใน Milestone 0 (มีค่าที่เสนอไว้ ถ้าผู้ใช้ตอบ "ตามที่เสนอ" ใช้ค่านี้)

1. นอกจากตัด/ถม งานจริงมีเงื่อนไขที่ใช้บ่อยอะไรอีก (เช่น ถมสูงเกิน X ให้มีขั้นบันได, ต่ำกว่าระดับน้ำให้มีหินทิ้ง) — ใช้ทำตัวอย่าง/ปุ่มสำเร็จรูปรอบหน้า
