# Viewer: opening and editing .cs files, assemblies, surface, simulator

Thai labels in quotes are the text shown in the web.

## Opening a .cs file (Import)

**"ไฟล์ ▾" → Import .cs** (or right-click an assembly), then choose:
- **"ไฟล์ในโฟลเดอร์นี้"**: put the file in this folder; the web reads only top-level `.cs` files (no subfolders). To use another folder, edit `"SubassemblyFolder"` in `SA.Web\appsettings.json`.
- **"เปิดจากเครื่อง…"**: a file from anywhere; in Chrome or Edge the web also follows saves of that file. (After a page refresh, that item uses the remembered code; Import again to keep following the file.)
- **"+ สร้างไฟล์ใหม่จาก template"**: creates a new `.cs` in the folder (crest of width Width + fill/cut slopes reaching Target Surface) and opens the code panel.

The first item of an assembly attaches to the axis by itself (like the old single-file mode); later ones float above the axis.

Files generated by the web (containing `// sa-spec`) load their drawn part both on Import and on **Edit** of a project item that stores only the file name (round 4e; previously Edit gave an empty drawn part).

A `.cs` file must have a public class with a `public void Draw()` method (the same one the `.atc` calls). With several classes in one file, a dropdown in that subassembly's Properties picks the class.

## Editing code in the web

- **"✎ แก้โค้ด"** (or `Ctrl+E`) opens / closes the code panel for the selected subassembly; drag the panel's right edge to resize. Selecting another item in the tree switches the panel to that item's file.
- After typing, the drawing updates once you stop for ~0.4 s (using the panel's code even if unsaved).
- **Auto-save to file** after ~1 s without typing (`Ctrl+S` = save now), preserving the file's format (BOM, CRLF/LF).
- Compiler errors appear as squiggles · click a line in the red box to jump to that code.
- **The same file can be edited in Antigravity at the same time.**
  - Nothing unsaved in the web → the web reloads the new version from the file (Ctrl+Z goes back).
  - Unsaved changes in the web → auto-save stops and you choose "เก็บฉบับในเว็บ" or "ใช้ฉบับในไฟล์" (never overwrites silently).
- Files opened with **"เปิดจากเครื่อง…"**: Chrome/Edge can save back to the original file (the browser asks permission the first time). Other browsers can edit in the web but you must press **"ดาวน์โหลด"** yourself.
- The editor is Monaco (the same as VS Code), loaded from the internet (cdn.jsdelivr.net). If it cannot load, a plain text box is used: saving and drawing still work, but no colouring / squiggles.

## Hung code (endless loop / recursion)

When compiling, the web inserts checkpoints at the start of every loop and method (in memory only; the real file is not changed and line numbers do not shift).

- Running longer than **3 seconds** → actually stopped and reported as Timeout with the hung line (even if the code has its own `catch (Exception)`).
- Abnormally deep recursion → stopped before the stack overflows (this used to take down the whole web).
- Hanging where there is no loop, e.g. `Thread.Sleep` → the web gives up waiting at 6 seconds (the hung code keeps running in the background; if the web gets slow, close and reopen run-viewer).

**Security:** this web really compiles and runs C# on this machine and can write files in the folder. It is accessible only from `localhost` (setting in `SA.Web/Properties/launchSettings.json`). Do not change it to allow other machines on the network.

## Assembly (combining several subassemblies)

A workspace can hold several assemblies (right-click the Workspace → **"+ Assembly ใหม่"**). Each has its own ⊞ axis and they share the surface line.

1. Import .cs into an assembly → the first attaches to the axis; later ones float above it (◇ dashed orange).
2. Drag the item (or its ◇ origin point) and drop near the **assembly axis** (⊞ dashed pink) or near a point of another subassembly (or select it, press `M`, click a base point → click the destination on the axis / a point; see [Move / Copy / Paste](drawing-tools.md#move--copy--paste)).
   - While dragging, circles mark attachable points; dropping near one (within ~14 px) attaches there.
   - Dropping away from all points = not attached (floating) · dragging an attached item away = detach.
   - Dropping on the axis or a point of **another assembly** = moves to that assembly (with the items attached to it).
3. The assembly axis can be dragged anywhere and attached items follow as a set · the axis elevation is numeric in the assembly's Properties.

- **Attach by point code** (e.g. `TrapTopOutside`): the attachment stays correct even when the point moves with the surface. A point with no code attaches by point index (the tree says "ไม่มี code" because the index can shift). If the parent no longer has that code, the tree shows ⚠ and the last position is used.
- Clicking an item in the tree or drawing → Properties / result bar (Messages / Log / Points) are for that item, and the code panel ("✎ แก้โค้ด") opens its file. Editing code redraws every item using the same file at once.
- Each item has its own parameters (one file can be used by several items, e.g. left / right) · **Rename** changes only the displayed name, not the file name.
- **Mirror** creates a copy on the opposite side (flips parameter `Side`) with everything attached to it.
- **Remove from assembly** (the `.cs` file is not deleted): items attached to it float where they are.
- **"ไฟล์ ▾" → Save project / Save project as…** stores `name.assembly.json` in this folder (parameters, attachments, axis, surface line, bottom-bar values). **Open project…** opens it (replaces the workspace) · files from the old Assembly mode open. A workspace with one assembly saves in the old format (older web versions can open it) · several assemblies use the new format (`version: 2`).
- Points in the result bar and Properties are **relative to the origin of the selected item** (the values the code gives `Points.Add`). Tooltips on the drawing and the bottom bar show offset from the assembly axis and real elevation.

In the simulator each item gets `CurrentOffset/CurrentElevation` = the real position of its attachment point, and `CurrentSubassemblyOffset/Elevation` = the attachment point relative to the assembly axis (per the API Reference).

Not supported yet: marked points (`ParamsPoint`), passing an output parameter of one item as input to another, offset/elevation targets.

## Surface line

- Drag a point = up / down · Shift+drag = also horizontal.
- Drag the line itself = shift the whole surface (SAC-style).
- Double-click the line, or press `A` then click on the line = insert a point.
- Right-click a point or `Delete` = delete the point · `F` = Fit · wheel = zoom · middle-mouse drag / `Space` + drag = pan (left-dragging the background = box select).
- Every surface edit is undoable with `Ctrl+Z` (a continuous drag = one step).
- Click **"Surface: EG"** in the tree (or the line) for Add point / delete point / reset buttons and options in Properties.
- Unticking "กำหนด surface ของเว็บให้ Target Surface" = simulate no assigned target.
- "ต่อปลายเส้นออกไปแนวราบ" (on by default) = an infinitely wide surface, like a real TIN larger than the section. Turn off to test code that asks for elevations outside the surface (you get PointNotOnEntityException).
- Mode = Layout simulates Civil 3D's Layout mode (Workspace Properties).

## Civil 3D API simulator (SA.Civil3DShim)

Only the parts subassemblies commonly use:

| Namespace | Contents |
|---|---|
| `Autodesk.Civil.Runtime` | `CorridorState` (ParamsLong/Double/String/Bool/Surface/Alignment/Profile, Points, Links, Shapes, Mode, Current*, RecordError, IntersectSurface, SampleSection), `Point`, `Link`, `Shape`, `CodeCollection`, `PointInMem`, `IPoint`, `SampledSectionLink` |
| `Autodesk.Civil` | `CorridorMode`, `CorridorError`, `CorridorErrorLevel`, `ParamLogicalNameType`, `PointNotOnEntityException` |
| `Autodesk.Civil.ApplicationServices` | `CivilApplication.ActiveDocument.CorridorState` |
| `Autodesk.Civil.DatabaseServices` | `Surface`/`TinSurface.FindElevationAtXY`, `Alignment.PointLocation/StationOffset` |
| `Autodesk.AutoCAD.DatabaseServices` | `ObjectId`, `OpenMode`, `Transaction`, `TransactionManager.GetObject`, `HostApplicationServices.WorkingDatabase` |
| `Autodesk.AutoCAD.Geometry` | `Point2d`, `Point3d` |

The simulator must never be more lenient than real Civil 3D. Shapes: the fill outline is built by walking the links in the order given to `Shapes.Add`, as Civil 3D does (`SA.Civil3DShim/ShapeWalk.cs`); links that do not chain give the same crossed fill as in Civil 3D plus the web warning `ShapeLinksNotChained`. `Link.Points` is a `PointCollection` (`Count`, indexer) as in the real API; `Link.StartPoint` / `EndPoint` do not exist in the real API and were removed.

If a `.cs` calls an API not present yet, the web shows a compile error such as `'CorridorState' does not contain a definition for 'XYZ'` → add it to the `SA.Civil3DShim` files (dotnet watch restarts by itself) or give Claude the function name to add.

Not supported yet: offset/elevation targets, several surfaces at once, superelevation, real profiles.
